# 匿名功能诊断

## 当前开发版

以最近公开发布的 Beta-0.4.4.2 为基线，Windows 和 macOS 的匿名诊断覆盖以下功能。

| 功能 | 诊断范围 |
| --- | --- |
| 部署与维护 | 工作账户和本土化设置保存、部署条件读取、Claude Code 官方下载与校验、目录新建与挂载重连、CloudCLI 打开与公网配置 |
| 连接与远程桌面 | 登录恢复、服务器资源与环境检测、启动远程桌面、保存显示模式 |
| 本地接入 | Claude Desktop SSH 接入、Codex 适配器、客户端启动、启停及自动恢复，Safe Code API Key 启停、恢复与通过本机转发的调用结果 |
| Safe Code API | 公网启用、状态与重连、打开管理窗口、Key 列表与用量读取、签发、修改、撤销、端口及公开地址设置 |

诊断默认关闭。旧版诊断授权升级后需要重新选择，之前已明确选择的基础统计授权单独保留。确认使用声明并在首次启动或「更新与反馈」中主动启用后，才会从新的操作开始收集。后台采样不会覆盖手动反馈关联的最近一次前台失败。关联编号由客户端随机生成。报告包含固定操作名、结果、耗时和已知错误类型，不读取原始日志目录，也不发送对话、请求或响应正文、API Key、激活码、地址、路径、用量明细或配置内容。服务端仍兼容旧版报告。

每种操作在一次启动中最多上报一次成功。每个客户端进程每小时最多尝试 20 份成功和 18 份失败或取消报告，其中后台最多使用 8 份成功和 6 份失败额度。同一后台操作与错误类型每小时最多一次。单份最多 12 秒，最多同时发送 2 份。接收端诊断每来源每小时最多 40 次。仍沿用 30 天诊断保留期，主动反馈及附带摘要保留 180 天。

SafeCode 关闭后，独立 VPS 网关的调用统计继续保存在该 VPS。匿名功能诊断由正在运行且已获授权的客户端发送。

接收端 schema 2 的新枚举应先上线，再发布新版客户端。本次改动复用既有接口、数据库和报表，已有 schema 1、schema 2 与手动反馈继续可用。

## 历史版本

2026-11-15 Beta-0.4.4.2 发布时，线上接收端已部署 macOS 平台兼容：允许 Windows 与 macOS 启动统计，仍拒绝未知平台。未增加采集字段或改变保留策略。脚本和 SQLite 一致性备份为 `/var/backups/safe-code-feedback/beta442-macos-20261115T134605Z`；双平台验收、未知平台拒绝、公网健康检查通过，合成数据精确清理，其他服务进程保持。

用户可在“更新与反馈”开启“同意自动上传匿名安装诊断”。默认关闭。旧版曾预勾选，升级后旧版选择重置为关闭，可按需重新开启。此开关独立于基础使用统计，仍需已确认声明。开启后，从下一次连接或安装操作开始收集。成功、失败及取消都会生成一份有界 JSON 诊断报告。声明确认前、验收模式及关闭状态不收集、不发送。关闭会立即取消在途请求，重新开启也不会补发之前的报告。

报告只含随机提交编号、软件版本、固定操作类型、成功/失败/取消、耗时、固定错误分类、固定代码位置、最多 64 个带相对秒数的步骤事件，以及被丢弃的未知日志行数。支持账户、本土化、桌面、Chrome、输入法、Claude、SSH、CloudCLI、挂载组件、目录挂载及这些任务的恢复监控。服务器记录接收时间。

原始日志不是报告的一部分：只将已知模式投影为固定词表，例如 `package_lock_wait`、`dns_failure`、`directory_not_found`、`account_draft_clear`。未识别的文本直接丢弃。这会牺牲部分排错细节，但避免依赖容易漏掉秘密的字符串替换。即使日志夹带密码、令牌、IP、邮箱、私钥、URL 或本地/远端路径，也不会将输入片段拼接进报告。报告没有安装编号、服务器标识、用户名、机器名、项目目录、原始异常、堆栈或文件内容，不读取历史日志目录。

每个进程最多尝试发送 20 份，最多同时发送 2 份；单份最多 12 秒，网络或 5xx 错误最多尝试 2 次，重试复用提交编号去重。无磁盘缓存、压缩包或离线积压，发送失败不会改变安装结果，也不会产生第二次报错。网络连接仍会让接收服务器与 Cloudflare 看见来源 IP，业务数据库不保存它。

服务端 POST `/v1/diagnostics` 严格校验每一层字段、枚举和数值范围，拒收额外文本。诊断保留 30 天，每次写入任一接口时清理过期项；共享现有 32KB 请求上限、数据库上限及代理全局限流，另按来源内存摘要限制为每小时 20 次。无公开查询接口，通过原有 SSH 运维读取：

```sh
python3 /opt/safe-code-feedback/report.py /var/lib/safe-code-feedback/data.sqlite3 --diagnostics
```

发布顺序：先备份并更新反馈服务的 `server.py`、`report.py`，重启该独立服务；再在专属 Nginx location 放行 `v1/diagnostics`，通过 `nginx -t` 后 reload；验证现有 usage/feedback/health 后再发布新客户端。升级仅新增 diagnostics 表，保留现有统计和反馈。2026-11-10 已完成线上接收端升级，HTTPS 验收和数据库回读通过；安装包随 Beta-0.4.3.3 发布。

本地验证包括反馈服务单测、`tools/SafeCode.Services.Verify` 的诊断隐私与授权检查，以及 `tools/test_diagnostics_ui.py` 的默认关闭、独立开关和小窗口可访问性检查。


## 反馈诊断升级（开发中，客户端尚未发布）

schema 2 与旧版 schema 1 同时接收。新版诊断增加固定阶段码、SSH 认证/连接/超时、网络错误、JSON 解析错误，以及远端传回的包管理锁、DNS、下载、挂载错误码。后台任务的错误码和错误文字分开传递，不通过原始异常文本上传细节。目录浏览也纳入诊断。

新版使用独立于使用统计的随机诊断安装编号、每进程会话编号、每操作问题编号；问题编号同时是上报 eventId，可关联重复操作并按编号查询。没有真实身份、硬件标识或服务器地址。新增字段改变了原先“诊断没有安装编号”的约定：升级后在原有声明页面确认一次新版须知，保留用户之前的开关选择，确认前不上报新版诊断。关闭诊断清除本地诊断安装编号、最近失败摘要，并取消在途/等待请求；重新开启会生成新编号。

成功诊断最多 2 份，失败/取消诊断独享 18 份额度，每进程最多 20 份；最多 2 份并发、有界排队，单份排队和发送合计最多 12 秒。未发送的报告不落盘，仍可能因离线、限流、退出或超时缺失，不能作为产品整体失败率分母。

失败提示显示问题编号。手动反馈保留原有表单，并在现有状态文字中说明将关联的问题编号。开启新版诊断时，提交会附带本进程最近一次失败（24 小时内）的固定字段摘要及关联编号；即使自动诊断未送达，反馈本身也能带回摘要。关闭诊断或没有失败记录时只提交手写文字及版本。诊断记录及关联数据保留 30 天，反馈内摘要及关联数据随反馈保留 180 天。用户须知在现有说明下方，不增加新表单。

接收端以新建 report_context 表保存关联信息，原 usage/feedback/diagnostics 表和历史行不迁移，旧版继续工作；清理过期记录时同步清理孤立关联行。report.py --feedback / --diagnostics 返回 context，旧数据库没有新表时也能读。

验证：服务端 16 项单测；客户端服务验证覆盖授权、迁移、失败独立额度、关联、关闭清除、敏感内容不上传、取消；远端错误协议 3 项测试；桌面项目跨平台编译及小窗口 UI 检查。未替代 Windows 实机和真实挂载验收。
