# 部署任务主机密钥校验失败排查

截图问题编号：`6ea1309a-8eab-4a08-be48-d2e2f94db5bd`。通过原有管理员 SSH 入口只读查询诊断数据库，未修改线上服务或用户服务器。

同一会话的 Beta-0.4.3.5 诊断显示：北京时间 2026-11-15 20:37 连接成功，20:46 工作账户部署成功（耗时 302 秒，包含大量软件包配置事件）；20:49 至 20:53 本土化连续六次失败，耗时 0–1 秒，均没有任务上传成功信号。截图报错为 `Host key could not be verified.`。因此错误发生在新建任务连接时，本土化命令尚未执行。

每次任务由 `MakeSftp` 新建 SFTP 连接，并将握手公钥与首次 SSH 连接的公钥逐字节比较。原实现没有限制后续连接的密钥算法。如果服务器系统更新后新增一种优先级更高的主机密钥，新连接会协商另一把密钥，尽管原密钥仍然可用，也会触发校验失败。

本机真实 SSH/SFTP 握手已复现：首次仅提供 RSA 密钥，随后保留该密钥并新增 ECDSA 密钥，修复前新 SFTP 连接报同样错误。此机制与现场记录吻合，但匿名诊断未保存服务器算法或密钥，不能据此证明现场具体新增了哪种密钥，也不能排除真实密钥替换或入口转发变化。

修复：新 SFTP、挂载及本机控制隧道、入口探测、工作用户公钥验证连接，只协商已确认公钥的密钥类型，并继续逐字节验证原公钥。RSA 保留库中 RSA SHA-2 签名算法及其原有优先顺序。首次连接的人工信任流程不变；不自动接受新密钥、不清空信任记录、不关闭校验。

验证命令：

```sh
.local/mount-fix-venv/bin/python tools/test_host_key_algorithms.py
.local/mount-fix-venv/bin/python tools/test_host_trust.py
.local/mount-fix-venv/bin/python tools/test_credential_recovery.py
```

算法回归测试覆盖真实 SFTP 与隧道握手：新增密钥类型仍能连接；替换原 RSA 密钥后两条通道均拒绝，密码认证次数为零。

现场恢复建议：返回登录并重新连接后再执行本土化，让新会话与任务通道重新协商一致的密钥。如弹出指纹变化提示，应先通过服务器控制台核对。重新连接属于临时恢复办法，不能保证修复真实密钥替换或入口错误。本次仅修改源码和测试，未发布安装包或替换用户正在运行的软件。
