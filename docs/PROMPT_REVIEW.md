# SafeCode 前置審查機制

「網關總覽 → 前置審查」首次安裝預設關閉，升級保留已儲存的審查設定。管理員可以選擇內置 Sonnet 或 Opus，也可以使用自己的 DeepSeek API Key 調用 DeepSeek Flash。開啟「安全審查」並儲存後，設定立即對該網關所有 API Key 的新請求生效。

## 審查範圍

SafeCode 在轉發用戶任務前，只取當輪用戶提示詞中的文字。歷史消息、附件、裝置憑據、工具輸出和應用的系統提示均不參與審查。通過後，原始任務照常經 SafeCode 網關、CloudCLI 和 Claude Code 處理。

內置模型透過已認證的 CloudCLI WebSocket，在獨立的審查項目中分類。每次建立新會話，提供全工具拒絕規則和 `dontAsk` 權限模式。項目配置關閉項目鉤子，禁止所有工具，並關閉項目 MCP 的自動啟用。收到工具活動事件時中止審查，完成後請求 CloudCLI 清理該審查會話。內置模式需要 CloudCLI 網頁授權，實際模型仍以 CloudCLI 的上游配置為準。

DeepSeek 模式只向 DeepSeek 官方 HTTPS 接口傳送當輪提示詞和分類規則。API Key 以權限為 `0600` 的檔案儲存在 VPS。管理頁只顯示儲存狀態，再次進入時可貼上新 Key 替換。

## 語言替換

「語言替換」預設關閉，開啟「安全審查」後可用。兩項均開啟時，網關讓同一個審查模型在放行結果中附上完整英文譯文。譯文應保留原提示詞的操作範圍、限制、明確指定的回覆語言、程式碼與路徑。通過後，網關將英文譯文作為任務文字交給 CloudCLI。拒絕、需要澄清和缺少有效譯文的請求均不會轉發。翻譯關閉時，通過審查的提示詞按原文轉發。

## 判定規則

| 請求意圖 | 處理方式 |
| --- | --- |
| 查詢已配對電腦任務、讀當前項目日誌、修改項目程式碼、執行測試、查看本機 WSL | 放行 |
| 解釋 Linux 磁碟格式化原理、翻譯引用的命令、整理含 `/etc` 的日誌、分析程式碼中的密鑰處理 | 放行 |
| 繼續上一輪、看下進度、修復當前倉庫；查詢公開倉庫文件或處理當前項目的依賴 | 放行 |
| 要求實際讀取或更改執行網關的伺服器，包括目錄、磁碟、系統服務、防火牆和管理配置 | 攔截並說明執行目標越界 |
| 要求讀取或修改其他用戶的會話、工作區或未授權項目，包括複製數據、調用其腳本或讓中間程式代為訪問 | 攔截並提示切換到有權限的工作區 |
| 要求獲取網關密鑰、管理令牌或繞過網關的訪問控制 | 攔截並說明涉及網關管理權限 |
| 明確要求執行高影響的系統操作，目標無法確定，例如只說「幫我格式化 Linux」 | 提示明確已配對裝置或當前工作區範圍 |

模型根據請求實際要求做什麼判斷，不能因為出現 Linux、密鑰或某個路徑就攔截。沒有明確越界意圖的普通任務按放行處理。一個請求同時包含正常任務和明確越界操作時，對這一輪返回警告，用戶可以刪除越界部分後重發。判斷結果只接受預設值，模型生成的其他文字不會作為指令或警告轉發。審查超時、模型不可用或返回格式異常時，這一輪返回可重試的 HTTP 503。

審查無法從一句話核實真實檔案權限，也無法完整覆蓋後續工具動作或跨輪上下文。它用於減少明顯越界請求，實際的檔案與裝置操作權限由各自的執行環境決定。
