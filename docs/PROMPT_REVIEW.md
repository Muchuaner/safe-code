# SafeCode 前置审查机制

「网关总览 → 前置审查」首次安装默认关闭，升级保留已保存的审查设置。管理员可以选择内置 Sonnet 或 Opus，也可以使用自己的 DeepSeek API Key 调用 DeepSeek Flash。打开「安全审查」并保存后，设置立即对该网关所有 API Key 的新请求生效。

## 审查范围

SafeCode 在转发用户任务前，只取当轮用户提示词中的文字。历史消息、附件、设备凭据、工具输出和应用的系统提示均不参与审查。通过后，原始任务照常经 SafeCode 网关、CloudCLI 和 Claude Code 处理。

内置模型通过已认证的 CloudCLI WebSocket，在独立的审查项目中分类。每次建立新会话，提供全工具拒绝规则和 `dontAsk` 权限模式。项目配置关闭项目钩子，禁止所有工具，并关闭项目 MCP 的自动启用。收到工具活动事件时中止审查，完成后请求 CloudCLI 清理该审查会话。内置模式需要 CloudCLI 网页授权，实际模型仍以 CloudCLI 的上游配置为准。

DeepSeek 模式只向 DeepSeek 官方 HTTPS 接口发送当轮提示词和分类规则。API Key 以权限为 `0600` 的文件保存在 VPS。管理页只显示保存状态，再次进入时可粘贴新 Key 替换。

## 语言替换

「语言替换」默认关闭，开启「安全审查」后可用。两项均开启时，网关让同一个审查模型在放行结果中附上完整英文译文。译文应保留原提示词的操作范围、限制、明确指定的回复语言、代码与路径。通过后，网关将英文译文作为任务文字交给 CloudCLI。拒绝、需要澄清和缺少有效译文的请求均不会转发。翻译关闭时，通过审查的提示词按原文转发。

## 判定规则

| 请求意图 | 处理方式 |
| --- | --- |
| 查询已配对电脑任务、读当前项目日志、修改项目代码、运行测试、查看本机 WSL | 放行 |
| 解释 Linux 磁盘格式化原理、翻译引用的命令、整理含 `/etc` 的日志、分析代码中的密钥处理 | 放行 |
| 继续上一轮、看下进度、修复当前仓库；查询公开仓库文档或处理当前项目的依赖 | 放行 |
| 要求实际读取或更改运行网关的服务器，包括目录、磁盘、系统服务、防火墙和管理配置 | 拦截并说明执行目标越界 |
| 要求读取或修改其他用户的会话、工作区或未授权项目，包括复制数据、调用其脚本或让中间程序代为访问 | 拦截并提示切换到有权限的工作区 |
| 要求获取网关密钥、管理令牌或绕过网关的访问控制 | 拦截并说明涉及网关管理权限 |
| 明确要求执行高影响的系统操作，目标无法确定，例如只说「帮我格式化 Linux」 | 提示明确已配对设备或当前工作区范围 |

模型根据请求实际要求做什么判断，不能因为出现 Linux、密钥或某个路径就拦截。没有明确越界意图的普通任务按放行处理。一个请求同时包含正常任务和明确越界操作时，对这一轮返回警告，用户可以删除越界部分后重发。判断结果只接受预设值，模型生成的其它文字不会作为指令或警告转发。审查超时、模型不可用或返回格式异常时，这一轮返回可重试的 HTTP 503。

审查无法从一句话核实真实文件权限，也无法完整覆盖后续工具动作或跨轮上下文。它用于减少明显越界请求，实际的文件与设备操作权限由各自的执行环境决定。
