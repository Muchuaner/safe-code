# 安装准备与 Claude Code 下载改进

用户在 214 Ubuntu 测试虚拟机安装 Claude Code 时，`claude.ai` DNS 解析失败，旧版将 curl 英文错误重复显示为安装失败。实测同一虚拟机能够解析 Ubuntu 软件源并访问其 HTTP/HTTPS 服务，不能据此判断整台虚拟机没有网络。

## 实现

首个安装任务在部署端先检查 APT/dpkg 锁，最多等待 15 分钟并显示中文进度；等待后完成未结束的软件包配置、更新软件源和当前 Ubuntu 版本的软件包，成功才写入完成记录并继续所选组件。升级允许新增依赖但禁止移除软件包，不执行发行版升级或自动重启。单独修改既有工作账户、配置 SSH 密钥不会触发全系统升级；之后安装依赖仍检查包管理器占用。失败不会误标记为准备完成。

完整测试包附带未修改的官方 Claude Code 2.1.311 Linux x64 文件，优先校验随包文件后经已验证主机密钥的 SSH 上传。未附带匹配架构文件的构建从官方发布服务获取稳定版、下载并缓存。两端分别校验 SHA256，后台安装任务保留自己的文件副本，避免断线导致上传临时文件失效。程序在普通工作用户的主目录中安装和运行，不以 root 执行用户可写程序，不代用户完成官方授权。

官方来源为 `https://downloads.claude.ai/claude-code-releases/2.1.311/linux-x64/claude`，SHA256 为 `86dc1fcc69498159eaf15f446613e847010f9036bfbbdffd4c49350be8489ada`，大小 293776752 字节。SHA256 来自同一官方 HTTPS 发布服务的 manifest；未另行验证 GPG 清单签名。随包文件及缓存不进入源码仓库。构建参数见 `tools/build_portable.py`。

DNS 错误显示具体域名和中文原因，HTTP 下载失败与超时单独说明，诊断保持固定错误码、不发送原始错误文本。原本的 `curl: (6) Could not resolve host: claude.ai` 会转换为“无法连接 claude.ai：DNS 域名解析失败，请检查服务器 DNS 或网络后重试。”

## 已完成验证

- 9 项自动检查通过，覆盖 DNS 中文错误及稳定错误码、HTTP 失败与 DNS 区分、更新成功/失败的完成记录、重复准备跳过、后台独立文件副本和非法安装路径拒绝。
- Windows Desktop 项目编译通过，0 警告、0 错误；诊断同意界面与独立指南的小窗口浏览器检查通过。
- 214 虚拟机实测通过“客户端下载官方文件、双端 SHA256 校验、SSH 上传、后台更新系统、普通工作用户安装”的完整路径。实际更新了 42 个系统软件包后，Claude Code 版本检查为 `2.1.311 (Claude Code)`，安装状态验证成功。该首轮使用的更新命令未新增内核依赖；最终代码增加 `--with-new-pkgs --no-remove`，此新增依赖参数已检查但未在虚拟机重新执行一次全系统升级。
- 系统更新后 SSH、xrdp 保持活动，双 IP 仍为 `192.168.50.66` 和 `192.168.174.30`。系统提示稍后重启，未重启虚拟机、214 宿主机或洛杉矶。

本次只交付独立测试包，尚未上传或发布正式 GitHub Release。程序文件可以随包安装，系统软件包更新仍需要访问软件源，Claude Code 的后续登录、自动更新和模型访问也仍需要网络；没有替换用户 DNS 或修改洛杉矶服务。
