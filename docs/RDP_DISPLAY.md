# Windows 远程桌面自适应与全屏验证

## 行为

窗口最大化后，旧实现仍保留初始远程桌面尺寸，在高分辨率显示器上可能留下灰边。本次使用 RDP ActiveX 的 `UpdateSessionDisplaySettings`，将远程画布与实际客户区同步，并增加当前显示器全屏、自动隐藏工具栏和 `Ctrl+Alt+Enter`。

窗口尺寸更新由 250 ms 定时器合并处理；连接建立后重试，失败最多尝试 20 次，后续尺寸变化或重新连接可再次触发。最小化时不更新。服务器不接受动态分辨率时保留 SmartSizing，不主动断开远程会话。

初始窗口增加 2560×1440、2560×1600 预设。全屏按钮、快捷键及界面提示仅适用于 Windows；macOS 保留原来的分辨率菜单和客户端操作。

## 可重复运行的本机检查

需要 Windows 交互式桌面、系统 RDP ActiveX 组件和 .NET 10 SDK。在仓库根目录执行：

```powershell
dotnet run --project tools/SafeCode.Desktop.Verify -c Release
```

检查会短暂显示真实 WinForms / ActiveX 窗口，不连接服务器、不读取登录配置。显示更新接口由记录调用的替身提供，可确定性测试服务器拒绝更新的路径。覆盖：

- 初始窗口、手动调整、最大化、最小化、超大预设适配工作区。
- 普通窗口和最大化窗口进入全屏，再退出时恢复几何尺寸和工具栏布局。
- 空闲时不重复请求、失败重试上限、新尺寸恢复请求、断线后重新连接。
- 关闭窗口时停止定时器、释放快捷键并断开客户端。

成功时最后输出 `DESKTOP_LAYOUT_AND_DISPLAY_UPDATES_OK`。它不代替真实服务器的协议协商和快捷键焦点验证。

## 真实服务器验收

在原 Beta-0.4.3.3 客户端上，本次相同的 `RdpDesktop.cs` 已使用 Windows x64（2560×1600 显示器、150% 系统缩放）与 Ubuntu 24.04 / xrdp / XFCE 验证：

| 操作 | 服务器 xrandr 返回的画布尺寸 |
| --- | --- |
| 初始窗口 | 1280×800 |
| 手动调整 | 1430×912 |
| 最大化 | 2560×1456 |
| 点击全屏 | 2560×1600 |
| 退出全屏 | 2560×1456 |
| RDP 获取焦点时用 Ctrl+Alt+Enter 进入 / 退出 | 2560×1600 / 2560×1456 |
| 2560×1600 预设适配工作区 | 2256×1410 |

安装到真实客户端后，从维护页打开远程桌面再次验证全屏：本机窗口边界和服务器画布均为 2560×1600，XFCE 会话保持不变。迁移到最新主分支后重新通过构建和上述本机检查；未声称已完成新版安装包的全部功能验收。

维护者复验时可在远程桌面内打开终端运行 `xrandr --current`，对照窗口客户区尺寸；全屏等待工具栏隐藏，确认无灰边。测试不同屏幕时应以实际屏幕和工作区尺寸为准，不硬编码上表。

尚未覆盖：混合 DPI 多显示器切换、显示器热插拔、所有 Windows / RDP 服务端版本。未改动 macOS 原生远程桌面实现，也未在 macOS 运行此 Windows 检查程序。
